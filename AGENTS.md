# Architecture
- Keep editable Turni-Pass data in the existing TurnState and undo history; store only capability-link snapshots in pass_shares to avoid a second source of truth.
- Rebuild existing pass-share snapshots transactionally from app_state with a database trigger; revoke disabled or orphaned shares so resets, transfers and cloud writes cannot leave stale public data.
- Public pass access requires an exact cryptographic token through a server function; never grant anonymous table access or expose private student fields.
- Reuse the same pass-sheet component for teacher and read-only public views; pure pass rules and payload projection live in a browser-safe module.
- Keep grading calculations in the browser-safe grading module, re-exported by TurnState, so student server reads use exactly the teacher formula without importing the client store.
- Student access uses hashed random codes and revocable database sessions in HttpOnly cookies; server reads project only the authenticated student's live app_state data, keeping student sessions separate from teacher authentication.
- Student login PDFs use owner-authenticated server validation and transient browser blobs; retain hash-only code storage, require explicit confirmation before regenerating unavailable codes, and never persist PDFs or plaintext credentials.
- Store uploaded exercise images as storage paths and resolve short-lived signed URLs on reads; storage policies allow only owners, administrators, and authenticated readers of approved exercises so pending images remain private.
- Version live pass-template upgrades once at store ingress, preserving exercise IDs, marks and optional exercises; leave archived passes unchanged to preserve historical records.
- Serve fixed pass templates as same-origin static PDF and original DOCX downloads so visitors can download without client-side document generation.
